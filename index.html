How matching works

Your idea is lowercased, split into words, stopwords removed (a, the, for, …), and lightly stemmed (farmers → farmer). A few synonyms are expanded — e.g. autotitrator → lab, device, diagnostic, pads → sanitary, menstrual, hygiene, tutor → education, student.

Each programme is then scored:

  • +5 if a word matches a word in the programme's name
  • +3 if a word matches one of the programme's keywords
  • +2 if a word appears in its eligibility text
  • +2 India bonus if you're India-based and the programme is India-eligible; −5 if it's explicitly not India-eligible
  • +2 if the stage fits (exact stage; +1 for the adjacent early stage, e.g. an idea-stage founder eyeing a prototype grant)
  • +2 baseline for open-topic programmes (any domain / anyone / any sector) so a vague idea still returns something
  • +1 tie-breaker for Hidden Gems and Top Picks

Match % = your score ÷ the best score in this run × 100. ≥70% Strong match · 40–69% Good match · <40% Worth a look. If nothing scores, open-topic programmes sorted by amount are shown instead. Keywords for all 185 programmes were generated by enrich.py from the research files — see README.md. Two deliberate guards: "india" never scores via name/keywords (it would swamp every domain signal — the India bonus handles it), and generic name words like lab, student, university, fellowship don't earn the +5 name bonus.

➕ Add a grant

No backend — fill this in, copy the JSON snippet, and paste it into grants.json (or send it as a pull request / issue on GitHub). Fields marked * are required. Keywords are optional here — run python3 enrich.py afterwards and it will generate them from your text.


    
To add it permanently: open grants.json, add the object to the array (keep it valid JSON — check with python3 -m json.tool grants.json), commit and push. GitHub Pages redeploys automatically.
